# CLI reference

> Generated by `tools/gen-docs` from the GATF sources. Do not edit this page by hand: change the source or `tools/gen-docs/descriptions/cli.properties`, then run `java tools/gen-docs/GenDocs.java generate`.

The installer puts a `gatf` launcher on your `PATH`. Without the installer, run the jar directly: `java -jar gatf-alldep-5.0.1.jar <command> …` (the release asset; a source build produces `gatf-alldep-jar-5.0.1.jar`) accepts every jar command below (not the launcher-only ones). Exit codes: `0` when every test passed or was flaky, `1` when a test failed, the run aborted or the command line was invalid (`gatf generate` also uses `2`; see its flags).

## Launcher commands

Handled by the `gatf` script itself (`dist/bin/gatf`; `gatf.cmd` on Windows mirrors it).

| Command | Syntax | Description |
|---|---|---|
| `ui` | `gatf ui [port] [dir]` | Starts the web console by running the jar's `-configtool` mode: `gatf ui [port] [dir]`. Port defaults to `9080`, directory to the current one, and the bind host to `$GATF_UI_HOST` or `127.0.0.1`. |
| `grid` | `gatf grid up\|down\|status [b]` | `gatf grid up\|down\|status [chrome\|firefox\|edge]` manages an official `selenium/standalone-<browser>` Docker container on port `4444` (browser defaults to `chrome`). `up` prints an `export SELENIUM_REMOTE_URL=...` line, `down` removes the container, and `status` exits 0 when the grid is ready and 1 when not; any other subcommand exits 2. |
| `tools` | `gatf tools install [tool...]` | `gatf tools install [tool...]` provisions load-test tools and prints the launch command each one resolves to on this machine, or `UNAVAILABLE` when it cannot be set up. With no tool names it provisions `wperfk`, `vegeta`, `autocannon`, `wrk` and `wrk2`; the leading `install` word is optional. |
| `version`, `--version`, `-v` | `gatf version` | Prints `gatf <version>` (from the `VERSION` file next to the launcher, else `unknown`) followed by the first line of `java -version`. `--version` and `-v` do the same on the shell launcher, and the command exits 0. |
| `help`, `-h`, `--help` | `gatf help` | Prints the launcher usage text and exits 0. It is also shown when `gatf` is run with no arguments, and on the shell launcher for `-h` and `--help`. |
| *(anything else)* | `gatf <jar command> …` | Any first argument that is not `ui`, `grid`, `tools`, `version` or `help` is passed unchanged to the jar (`java -jar lib/gatf.jar ...`), so `test`, `docs`, `import`, `export`, `plan`, `generate`, `merge-reports`, `mcp` and the `-executor` style modes work directly. Extra JVM flags come from `$GATF_JAVA_OPTS`. |

### gatf -generator

`-generator <config>.xml|json` reads a generator configuration and generates API test cases from the configured source (JAX-RS or Spring classes, or WSDL). The file must end in `.xml` or `.json`; any other extension prints the usage text and exits 1.

```text
gatf -generator {generator-config-file}.xml
```


### gatf -executor

`-executor <config>` runs an API suite and `-selenium <config>` runs a UI (seleasy) suite from the given `.xml` or `.json` config, using the current directory as the base path for test cases and output. It prints a quiet console summary, writes the CI reports, and exits 1 when any test failed or the run aborted. `gatf test` uses the same run path.

```text
gatf -executor {executor-config-file}.xml
gatf -selenium {selenium-config-file}.xml
```


### gatf test

`gatf test [config] [options]` runs the suite in `config`, defaulting to `gatf-config.json` and then `gatf-config.xml` in the working directory. API or UI is decided by the config's `isSeleniumExecutor`. Exits 1 on failed tests, an aborted run or invalid arguments, and 0 otherwise.

```text
gatf test [config] [--grep RE]... [--grep-invert RE]... [--tag T]... [--reporter junit,json,github,docs|none]
          [--trace off|on|retain-on-failure|on-first-retry] [--retries N] [--workers N|N%] [--shard i/n] [--forbid-only]
          [--update-snapshots] [--watch] [--changed <git-range> [--explain] [--coverage-run dir] [--source-maps dir]]
```

| Flag | Description |
|---|---|
| `--changed` | Takes a git range (for example `main...HEAD`) and runs only the UI scripts the change can reach, using the coverage index from an earlier traced run. When it cannot decide safely it runs everything and says why; when no script is affected it runs nothing and exits 0. UI suites only, and cannot be combined with `--watch`. |
| `--coverage-run` | Folder of the earlier run whose traces form the coverage index for `--changed`; defaults to the newest run folder in the output directory. Only valid together with `--changed`. |
| `--explain` | With `--changed`, prints each script with a run or skip verdict and the reason, and runs nothing (exit 0). Only valid together with `--changed`. |
| `--forbid-only` | Fails the run if a subtest is marked `only`. A bare flag; overrides the config's `forbidOnly` for this run. |
| `--grep` | Runs only tests whose title matches this regular expression (find semantics, case-sensitive). Repeatable; multiple `--grep` and `--tag` values are ORed, and the dependencies of a selected API test are pulled in. An invalid regex exits 1. |
| `--grep-invert` | Excludes tests whose title matches this regular expression, applied after the include filters. Repeatable. |
| `--reporter` | Comma-separated CI reports to write to the output folder: `junit` (`gatf-junit.xml`), `json` (`gatf-results.json`), `github` (annotations when `GITHUB_ACTIONS=true`), `docs` (test-case documents under the report folder's `docs`, which implies `json`) or `none`. Default is `junit,json,github`. |
| `--retries` | Number of times a failing UI script is retried; overrides the config's `seleniumScriptRetryCount`. Must be an integer of 0 or more. |
| `--shard` | Runs one slice of the test files, written `i/n` (1-based, for example `2/4`). Files are split deterministically by a hash of their path, so every machine computes the same split; a shard that gets no files is a green no-op. Combine the slices with `gatf merge-reports`. |
| `--source-maps` | Folder holding the scripts' external `.map` files, used by `--changed` to map changed build output back to sources. Only valid together with `--changed`. |
| `--tag` | Runs only tests carrying this `@tag`, with or without the leading `@`. Tags are `@word` tokens in an API test's name or description, or in the top `//` comment lines of a `.sel` file. Repeatable, ORed with `--grep`. |
| `--trace` | Trace recording mode: `off`, `on`, `retain-on-failure` or `on-first-retry`; overrides the config's `traceMode`. Any other value exits 1. |
| `--update-snapshots` | Rewrites the baselines of `screenshot compare` steps instead of failing on a difference. A bare flag; overrides the config's `updateSnapshots`. |
| `--watch` | Runs the suite, then watches the project: saving a file re-runs the changed scripts plus the last failures; Enter re-runs everything with failures first, `f` re-runs only the failures and `q` quits. Each run is a child JVM; cannot be combined with `--changed`. |
| `--workers` | Parallel workers; overrides the config's `numConcurrentExecutions`. Takes `N` or `N%` of the CPU cores (at least 1); UI scripts run file-parallel and never more workers than scripts are used. |
| `-g` | Same as `--grep`. |
| `-j` | Same as `--workers`. |
| `-t` | Same as `--tag`. |
| `-u` | Same as `--update-snapshots`. |


### gatf docs

`gatf docs [config...] [options]` writes test-case documents, a requirements traceability matrix and coverage from the configured tests, into `gatf-docs` unless `--out` is given. Uses `gatf-results.json` from the config's output folder for status when present; exits 1 on a usage or read error.

```text
gatf docs [config...] [-o <dir>] [--format xlsx|csv|both] [--requirements <file.csv|xlsx>] [--results <gatf-results.json>] [--req-pattern <regex>] [--requirements-jql <JQL>]
```

| Flag | Description |
|---|---|
| `--format` | Output format: `xlsx`, `csv` or `both` (default `both`). Any other value is an error and exits 1. |
| `--out` | Output directory for the documents, traceability matrix and coverage; defaults to `gatf-docs` in the working directory. |
| `--req-pattern` | Regular expression matched against the `@tag` tokens in test names, descriptions and script comments to find requirement IDs; the first capture group (else the tag without `@`) is the ID. An invalid pattern exits 1. |
| `--requirements` | Requirements list as a `.csv` or `.xlsx` file (columns `id`, `title`, `module`) for the traceability matrix. The file must exist. |
| `--requirements-jql` | Jira JQL query whose issues are imported as requirements, using Jira settings from environment variables. Rows from `--requirements` win on duplicate IDs. |
| `--results` | Path to a `gatf-results.json` supplying each test's status. Defaults to the one in the config's output folder when it exists, else every test is `not run`. |
| `-o` | Same as `--out`. |


### gatf import

`gatf import <type> <file|-> [options]` converts an external artifact (Playwright spec, JMeter plan, cURL commands, Postman collection, HAR, OpenAPI/Swagger, or a run's `network.har` as a load test) into a GATF test file and lists what could not be carried over. `-` reads the input from stdin. Refuses to overwrite an existing output without `--force`; exits 1 on error.

```text
gatf import <playwright|jmeter|curl|postman|har|openapi|flow> <file|-> [-o <out-file>] [--name <suite>] [--filter <url-regex>] [--negative] [--force]
          flow (a run's network.har → load test): [--users N] [--duration S] [--rate R] [--engine wperfk|vegeta|autocannon|wrk|wrk2] (default wperfk)
```

| Flag | Description |
|---|---|
| `--duration` | Load-test duration for the `flow` import type (a run's `network.har` converted to a load test); passed through as given. Ignored by the other types. |
| `--engine` | Load tool for the `flow` import type: `wperfk`, `vegeta`, `autocannon`, `wrk` or `wrk2`; defaults to `wperfk`. |
| `--filter` | Regular expression on the request URL; only matching requests are imported. |
| `--force` | Overwrites the output file (and any side files) if it already exists; without it an existing file exits 1. |
| `--name` | Suite name for the generated file. Defaults to the input file name without extension, or `imported-<type>` for stdin. |
| `--negative` | For the `openapi` and `swagger` types, also generates negative test cases. Ignored by the other types. |
| `--out` | Output file path. Defaults to the name the importer chooses (for OpenAPI, `<name>.xml`) in the working directory. |
| `--rate` | Request rate for the `flow` import type; passed through as given. Ignored by the other types. |
| `--users` | Concurrent users for the `flow` import type; passed through as given. Ignored by the other types. |
| `-f` | Same as `--force`. |
| `-o` | Same as `--out`. |


### gatf export

`gatf export <target> <file.sel|dir> [options]` exports seleasy scripts to another framework (targets `playwright` and `selenium-java`) and prints what was not carried over. A directory exports every `.sel` file that has an `open` statement and also writes `export-report.txt`. Exits 1 on any error or failed script.

```text
gatf export <playwright|selenium-java> <file.sel|dir> [-o <out-file|out-dir>] [--strict-locators] [--force]
```

| Flag | Description |
|---|---|
| `--force` | Overwrites existing output files; without it an existing target exits 1. |
| `--out` | Output file for a single `.sel` input, or output directory for a directory input. Defaults to the generated file name in the working directory, or `export-<target>` for a directory. |
| `--strict-locators` | Makes semantic locators strict in the exported code: they must match exactly one element. Off by default, where every locator acts on its first match, as seleasy does. |
| `-f` | Same as `--force`. |
| `-o` | Same as `--out`. |


### gatf plan

`gatf plan <crawl-coverage.json> [options]` turns a crawl map into a test plan written as JSON (`<name>-plan.json`) and Markdown beside the map. Every crawled route gets an entry with or without AI; the config's `ai` block only enriches it. Never overwrites existing outputs without `--force`.

```text
gatf plan <crawl-coverage.json> [-o plan.json] [--md plan.md] [--config cfg] [--no-ai] [--max-routes N] [--coverage-run dir] [--force]
```

| Flag | Description |
|---|---|
| `--config` | Config file whose `ai` block enriches the plan. Defaults to `gatf-config.json`, else `gatf-config.xml`, in the working directory; without one (or with a missing file) the plan is built without AI. |
| `--coverage-run` | Run folder whose traces mark which routes were already visited, so the plan can account for them. |
| `--force` | Overwrites existing plan files; without it an existing output exits 1. |
| `--help` | Prints the usage line and exits 0. |
| `--max-routes` | Maximum number of routes to plan, an integer from 1 to 5000; the default is 500. Routes beyond the cap are reported as not planned. |
| `--md` | Markdown output path. Defaults to the JSON output name with a `.md` extension. |
| `--no-ai` | Builds the plan without calling the AI client, so no AI-proposed journeys are added. |
| `--out` | JSON plan output path. Defaults to `<name>-plan.json` beside the crawl map, where `<name>` is the map's file name without `-coverage.json`. |
| `-f` | Same as `--force`. |
| `-h` | Same as `--help`. |
| `-o` | Same as `--out`. |


### gatf generate

`gatf generate <n>-plan.json [options]` turns a test plan from `gatf plan` into seleasy scripts, each checked by the script validator and a dry-run compile. Only passing scripts are written, by default to `tests/generated/<plan name>/`. Exits 0 when all pass, 2 when some scripts fail the gate, and 1 on a usage or I/O error.

```text
gatf generate <n>-plan.json [-o dir] [--config cfg] [--ai|--no-ai] [--include-side-effects] [--force]
```

| Flag | Description |
|---|---|
| `--ai` | Uses AI for the repair loop when the config has an `ai` block (the default). Cancels an earlier `--no-ai`. |
| `--config` | Config file that gives the script gate its project settings and the `ai` block. Defaults to `gatf-config.json`, else `gatf-config.xml`, in the working directory; one must exist or the command exits 1. |
| `--force` | Overwrites existing scripts in the output folder; without it an existing script exits 1 and nothing is written. |
| `--help` | Prints the usage line and exits 0. |
| `--include-side-effects` | Also generates journeys that have side effects, which are skipped by default and listed in the summary. |
| `--no-ai` | Generates and gates without the AI repair loop. |
| `--out` | Output directory, which must be inside the working directory. Defaults to `tests/generated/<plan name>`. |
| `-f` | Same as `--force`. |
| `-h` | Same as `--help`. |
| `-o` | Same as `--out`. |


### gatf merge-reports

`gatf merge-reports <dir> <dir>... [options]` merges the output folders of a sharded run into one report (`gatf-results.json`, `gatf-junit.xml`, `index.html`, a copy of each input as `shard-<i>-of-<n>`). Exits 1 when the merged results contain failures or on error, else 0.

```text
gatf merge-reports <dir> <dir>... [-o out-dir]   (default out-dir: merged-report)
```

| Flag | Description |
|---|---|
| `--out` | Output directory for the merged report; defaults to `merged-report` in the working directory. Also accepted as `--out=<dir>`. |
| `-o` | Same as `--out`. |


### gatf mcp

`gatf mcp [--root <project-dir>]` starts an MCP server on stdio for coding agents, exposing the tools `list_tests`, `lint`, `run`, `get_report`, `summarise_trace`, `record` and `crawl`. Only JSON-RPC goes to stdout; logs go to stderr.

```text
gatf mcp [--root <project-dir>]   (MCP stdio server: list_tests, lint, run, get_report, summarise_trace, record, crawl)
```

| Flag | Description |
|---|---|
| `--help` | Prints the usage line to stderr and exits 0. |
| `--root` | Project directory the MCP tools operate on; defaults to the working directory and must exist. Also accepted as `--root=<dir>`. |
| `-h` | Same as `--help`. |
| `-r` | Same as `--root`. |


### gatf -configtool

### gatf -validate-sel

`-validate-sel <file.sel> [config] [workdir] [log]` compiles a seleasy script without running it and prints `SUCCESS` or `FAILURE` (with the compile error on stderr). `config` defaults to `gatf-config.json` if present in `workdir`, else `gatf-config.xml`; `workdir` defaults to `/workdir`, and a `file` without a path separator is looked up under `/workdir/`. A fifth value `true` enables logging. The process exits 0 in both cases.

```text
gatf -validate-sel {file-name/relative/to/workdir} [{config-file} [{workdir, default /workdir}]]   (exits 1 when the script does not validate)
```
