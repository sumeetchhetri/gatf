# Configuration reference

> Generated by `tools/gen-docs` from the GATF sources. Do not edit this page by hand: change the source or `tools/gen-docs/descriptions/config.properties`, then run `java tools/gen-docs/GenDocs.java generate`.

The executor configuration is one file, `gatf-config.json` or `gatf-config.xml` (`gatf test` uses the JSON one when both exist). Every field below is optional. In JSON a field is a key; in XML it is an element of the same name under `<gatf-execute-config>`, and a list is a wrapper element whose children may have any name (for example `<seleniumScripts><string>a.sel</string></seleniumScripts>`). Paths are relative to the project folder unless noted. The [configuration concept page](../guide/concepts/configuration.md) explains how the pieces fit; this page lists every field.

**Default** is the value when the field is absent. For fields marked *(unset)* GATF falls back to the behaviour described.

## GatfExecutorConfig

The executor configuration: the root `gatf-execute-config` element of `gatf-config.xml`, or the top-level object of `gatf-config.json`. It controls API suites (base URL, auth, HTTP client, load and comparison runs) and seleasy UI suites (scripts, browsers, tracing, waits, setup scripts). XML root element: `<gatf-execute-config>`. Source: [`GatfExecutorConfig.java`](https://github.com/sumeetchhetri/gatf/blob/master/alldep-jar/src/main/java/com/gatf/executor/core/GatfExecutorConfig.java).

| Field | Type | Default | Description |
|---|---|---|---|
| `baseUrl` | `String` | *(unset)* | Base URL used by every API test case that has no `baseUrl` of its own. In comparison runs it is the first environment, compared against `gatfTestDataConfig.compareEnvBaseUrls`. |
| `testCasesBasePath` | `String` | *(unset)* | Root directory of the project; `testCaseDir`, data files and `gatf-logging-api-int.xml` are resolved under it. When unset the web console uses its own root directory (in memory only, so the saved config stays portable); a set path must exist. |
| `testCaseDir` | `String` | *(unset)* | Sub-directory of `testCasesBasePath` holding the test files (`.xml`, `.json`, `.csv`, `.sel`). Blank or `.` means `testCasesBasePath` itself; when set it must exist. Resource files named in the config are looked up here first, then in `testCasesBasePath`, then as given. |
| `outFilesBasePath` | `String` | *(unset)* | Root directory for run output (reports, traces, logs). When unset the web console uses its own root directory (in memory only); a set path must exist. |
| `outFilesDir` | `String` | *(unset)* | Sub-directory of `outFilesBasePath` that receives the reports. The web console sets `out` when it is unset and creates the directory if it is missing. |
| `authEnabled` | `boolean` | `false` | Turns on automatic authentication for API suites: the case whose `url` equals `authUrl` runs first, its token is extracted as `authExtractAuth` describes, and every `secure` case then carries it. When `true`, `authUrl`, `authExtractAuth` (4 parts) and `authParamsDetails` (4 parts) are validated at load. |
| `authUrl` | `String` | *(unset)* | URL of the login test case (matched against each case's `url`). That case runs before the others; for later `secure` cases the token is added unless the request goes to this URL. |
| `authExtractAuth` | `String` | *(unset)* | Four comma-separated parts `tokenName,source,variable,usage`. `source` is `json`, `xml`, `plain`, `header` or `cookie` (where `tokenName` is read from the login response); the value is stored as workflow variable `variable`; `usage` (`queryparam`, `header` or `cookie`) is how `secure` cases send it. |
| `authParamsDetails` | `String` | *(unset)* | Four comma-separated parts `userParam,userMode,passwordParam,passwordMode` telling the login case where to put the credentials taken from `authDataProvider`; modes are `header`, `postparam`, `queryparam` or `content`. The two param names are also the column names read from the provider rows. |
| `wsdlLocFile` | `String` | *(unset)* | File listing SOAP services, one `wsdlKey,wsdlUrl` line each. Each WSDL is parsed at start-up to build the request templates, SOAP actions and endpoints that SOAP test cases (`wsdlKey` + `operationName`) use. |
| `soapAuthEnabled` | `boolean` | `false` | Turns on token authentication for SOAP cases: the case identified by `soapAuthWsdlKey` + `soapAuthOperation` runs first, and `secure` SOAP cases get the token appended to their endpoint as a query parameter. |
| `soapAuthWsdlKey` | `String` | *(unset)* | `wsdlKey` of the SOAP login operation (see `wsdlLocFile`); required when `soapAuthEnabled` is `true`. |
| `soapAuthOperation` | `String` | *(unset)* | Operation name of the SOAP login call; with `soapAuthWsdlKey` it identifies the auth case. Required when `soapAuthEnabled` is `true`. |
| `soapAuthExtractAuth` | `String` | *(unset)* | Three comma-separated parts `tokenName,paramName,queryparam`, validated when `soapAuthEnabled` is `true` (the third must be `queryparam`). The token is appended to `secure` SOAP endpoints as `paramName=<token>`; it is looked up through the variable named in `authExtractAuth`. |
| `numConcurrentExecutions` | `Integer` | *(unset)* | Parallelism. API suites: thread-pool size for running test cases in parallel (used when above 1 and there is more than one test). UI suites: the number of scripts run in parallel. Loaders fill `1` when unset. |
| `httpCompressionEnabled` | `boolean` | `false` | Adds `Accept-Encoding: gzip` to API requests that do not set it; gzip responses are decoded. Some loaders (the Maven plugin default, the single-script seleasy loader) turn a `false` back on. |
| `httpConnectionTimeout` | `Integer` | *(unset)* | Connect timeout of the API HTTP client, in ms; null or 0 means no connect timeout. The web console and the seleasy loader fill `10000` when unset. |
| `httpRequestTimeout` | `Integer` | *(unset)* | Per-request timeout for API calls (and the `curl` plugin), in ms; applied only when above 0. The web console and the seleasy loader fill `10000` when unset. |
| `concurrentUserSimulationNum` | `Integer` | *(unset)* | Number of simulated concurrent users: above 1 the suite runs once per user (with `concurrentUserRampUpTime` spread across them) and reports show multiple runs. Above 1 also turns off UI tracing, and stateful file providers get one data file per user. |
| `testDataConfigFile` | `String` | *(unset)* | Path to a separate test-data file (`.xml`, otherwise JSON) holding a `gatfTestDataConfig` block. When set it is loaded at start-up and replaces the inline `gatfTestDataConfig`; the file must exist. |
| `authDataProvider` | `String` | *(unset)* | Name of the data provider whose rows supply the login credentials for the `authUrl` case (columns named by `authParamsDetails`). The row is picked by the case's simulation number, or at random when there are fewer rows. |
| `compareEnabled` | `boolean` | `false` | Comparison mode: each API case is run against `baseUrl` and every URL in `gatfTestDataConfig.compareEnvBaseUrls`, and the responses are compared. It needs at least one compare URL different from `baseUrl`, and it turns load testing off. |
| `enableTrace` | `boolean` | `false` | Legacy switch for the UI trace recorder: used only when `traceMode` is unset (`true` = `on`, `false` = `off`). Traces are captured for functional UI runs only (not load runs or more than one simulated user), on Chromium or BiDi browsers. |
| `traceMode` | `String` | *(unset)* | When to capture and keep a UI trace: `off`, `on`, `retain-on-failure` (keep only failed scripts' traces) or `on-first-retry` (capture only in the first retry round). Blank falls back to `enableTrace`; any other value is rejected when the config is loaded. |
| `traceProtocol` | `String` | `cdp` | Transport the trace recorder uses: `cdp` (default), `bidi`, or `hybrid` (BiDi, plus CDP for CPU, coverage and video). Browsers without DevTools always use BiDi, and the worker browser pool may switch a run to `bidi`. It is also the default protocol for `route` interception (`-Dgatf.routeProtocol` overrides). |
| `browserApiSession` | `String` | *(unset)* | How `api`/`curl` plugin calls made from a UI script share the browser session: `sync` (default; send the browser's cookies and store `Set-Cookie` back into the browser), `send` (send only) or `off`. Other values are rejected at load. |
| `perfBudgets` | `String` | *(unset)* | Performance budgets checked against each UI script's trace, as comma-separated `metric<limit` items (e.g. `lcp<2500, requests<80, jsheap<50mb`). Metrics: `lcp`, `fcp`, `ttfb`, `dcl`, `load` (ms), `cls`, `jsheap`, `transfer`, `requests`, `failedRequests`, `consoleErrors`; unknown metrics or units are rejected at load, and a breach fails the script. Needs a captured trace. |
| `securityChecks` | `String` | *(unset)* | Passive security scan over each UI script's trace (mixed content, CSP, HSTS, clickjacking, cookie flags, CORS): `report` (default; findings in the report), `fail` (a medium or high finding fails the script) or `off`. Other values are rejected at load. |
| `autoWait` | `Boolean` | *(unset)* | When `true`, element actions wait until the element is actionable (attached, visible, enabled, stable, not covered) before acting, for up to `actionTimeout`. Unset or `false` keeps the old behaviour (no waiting). |
| `actionTimeout` | `Long` | *(unset)* | Auto-wait budget per action, in ms; null or 0 and below means 5000. Used only when `autoWait` is `true`. |
| `webFirstAssertions` | `Boolean` | *(unset)* | When `true`, `??` value assertions retry until they pass or `assertTimeout` runs out, instead of failing at once. Unset or `false` keeps the fail-at-once behaviour. |
| `assertTimeout` | `Long` | *(unset)* | Retry budget per web-first assertion, in ms; null or 0 and below means 5000. Used only when `webFirstAssertions` is `true`. |
| `testIdAttribute` | `String` | *(unset)* | Attribute that `testid@` locators match; unset means `data-testid`. The recorder, healer and crawler also use it when proposing locators. |
| `strictLocators` | `Boolean` | *(unset)* | When `true`, a semantic locator (`role@`, `label@`, `testid@` and so on) that matches more than one element fails and lists the candidates. Unset or `false` takes the first match. |
| `storageState` | `String` | *(unset)* | File for the browser storage state (cookies and web storage). Every UI script loads it right after its browser opens; the `loginOnce` script saves its state to it when it finishes. |
| `loginOnce` | `String` | *(unset)* | Script run once before the UI suite (first round only) to log in; its browser state is saved to `storageState` so the suite's scripts start logged in. It is never run as one of the suite's scripts; without `storageState` the login is not saved (a warning is printed). |
| `browserContexts` | `String` | *(unset)* | Per-test browser isolation: `subtest` = every top-level subtest runs in a fresh browser context of the script's browser; `worker` = each worker keeps one browser and every script runs in a fresh context of it. Unset, `off` or any other value keeps the shared context. |
| `globalSetup` | `String` | *(unset)* | Script run once before the UI suite (before `loginOnce`), only in the first round. It is never run as a suite script, and if it fails the run stops. |
| `globalTeardown` | `String` | *(unset)* | Script run once after the UI suite's last round, also when the suite failed. It is never run as a suite script. |
| `browserApiStorageToken` | `String` | *(unset)* | Web-storage entry holding a bearer token that `api`/`curl` plugin calls from UI scripts send as `Authorization` (unless the case sets that header), written `[localStorage:\|sessionStorage:]key[#json.field]`. Unset = no token. |
| `browserApiStorageTokenHosts` | `String[]` | *(unset)* | Extra hosts (`host`, or `*.domain` for a domain and its subdomains) that `browserApiStorageToken` may be sent to besides the open page's own host. The token is never sent from an https page to plain http. |
| `forbidOnly` | `Boolean` | *(unset)* | When `true`, a subtest marked `only` is a transpile error, so a focused test cannot slip into CI (the CLI flag `gatf test --forbid-only` does the same). Unset or `false` allows it. |
| `updateSnapshots` | `Boolean` | *(unset)* | When `true`, `screenshot compare` rewrites its baselines instead of comparing (also `-Dgatf.updateSnapshots=true` or `gatf test --update-snapshots`). |
| `traceNetwork` | `boolean` | `true` | Record network requests and responses in the UI trace (default `true`). |
| `traceConsole` | `boolean` | `true` | Record browser console messages in the UI trace (default `true`). |
| `traceSnapshots` | `boolean` | `true` | Record page snapshots (DOM HTML plus a screenshot) in the UI trace (default `true`). |
| `traceMaxBodyKb` | `int` | `512` | Largest response body kept per request in the trace, in KB (default 512; 0 or less keeps the default). |
| `traceMaxTotalMb` | `int` | `64` | Total response-body budget per trace, in MB (default 64; 0 or less keeps the default). |
| `traceMetrics` | `boolean` | `true` | Sample browser performance and memory metrics into the trace every `traceMetricsIntervalMs` (default `true`). |
| `traceMetricsIntervalMs` | `int` | `1000` | Metrics sampling interval, in ms (default 1000; 0 or less keeps the default). |
| `traceWebVitals` | `boolean` | `true` | Record web vitals (FCP, LCP, TTFB, DCL, load) from the Performance Timeline in the trace (default `true`); `perfBudgets` on these metrics need it. |
| `traceCpu` | `boolean` | `false` | Record a CPU sampling profile in the trace (default `false`; adds overhead). Needs a CDP-capable browser (`cdp` or `hybrid`). |
| `traceCoverage` | `boolean` | `false` | Record JS and CSS coverage in the trace (default `false`; adds overhead). Needs a CDP-capable browser (`cdp` or `hybrid`). |
| `traceVideo` | `boolean` | `false` | Record a screencast video (mp4) of the page in the trace (default `false`; the heaviest option). |
| `traceVideoQuality` | `int` | `60` | JPEG quality of screencast frames, 1 to 100 (default 60; values outside that range keep the default). |
| `traceVideoEveryNthFrame` | `int` | `2` | Keep every Nth screencast frame (default 2; 0 or less keeps the default). |
| `traceDomSnapshots` | `String` | *(unset)* | Per-action DOM snapshots for time-travel in the Trace Viewer: `off`, `lite` (sanitized DOM, no stylesheets) or `full` (styled). Unset uses `-Dgatf.trace.domSnapshots`, else `off`; unknown values mean `off`. |

## GatfTestDataConfig

The `gatfTestDataConfig` block (inline in the executor config, or the whole of `testDataConfigFile`): global variables, comparison URLs, data sources, data providers and data-source hooks. It is set up when the run's context is initialised. XML root element: `<gatf-testdata-config>`. Source: [`GatfTestDataConfig.java`](https://github.com/sumeetchhetri/gatf/blob/master/alldep-jar/src/main/java/com/gatf/executor/dataprovider/GatfTestDataConfig.java).

| Field | Type | Default | Description |
|---|---|---|---|
| `globalVariables` | `Map<String, String>` | *(unset)* | Name/value map of project-wide variables, available as `${name}` in API cases and seleasy scripts. |
| `compareEnvBaseUrls` | `List<String>` | *(unset)* | Extra environment base URLs for comparison runs (`compareEnabled`); each case is replayed against `baseUrl` and each of these. |
| `dataSourceList` | [`List<GatfTestDataSource>`](#gatftestdatasource) | *(unset)* | Data sources (database connections) that providers and hooks refer to by name. |
| `providerTestDataList` | [`List<GatfTestDataProvider>`](#gatftestdataprovider) | *(unset)* | Data providers: named sets of variable rows used by API cases (`repeatScenarioProviderName`, `authDataProvider`) and seleasy loops. |
| `dataSourceHooks` | [`List<GatfTestDataSourceHook>`](#gatftestdatasourcehook) | *(unset)* | Named query lists run against a data source on start-up, on shutdown, or around a test case (`preExecutionDataSourceHookName` / `postExecutionDataSourceHookName`). |
| `dataSourceListForProfiling` | [`List<GatfTestDataSource>`](#gatftestdatasource) | *(unset)* | Separate data sources (pool size forced to 1) used only by the web console's data-source profiling view, together with `profile-providers.xml`. |

## GatfTestDataSource

One entry of `dataSourceList`: a named, pooled connection. Use `com.gatf.executor.dataprovider.SQLDatabaseTestDataSource` (args: JDBC URL, driver class, user, password), `com.gatf.executor.dataprovider.MongoDBTestDataSource` (args: host, port, database, optional user and password) or a custom class implementing `TestDataSource`. XML root element: `<gatf-testdata-source>`. Source: [`GatfTestDataSource.java`](https://github.com/sumeetchhetri/gatf/blob/master/alldep-jar/src/main/java/com/gatf/executor/dataprovider/GatfTestDataSource.java).

| Field | Type | Default | Description |
|---|---|---|---|
| `dataSourceName` | `String` | *(unset)* | Unique name of the data source; providers and hooks refer to it through their `dataSourceName`. Required. |
| `dataSourceClass` | `String` | *(unset)* | Implementation class: one of the built-in SQL or MongoDB classes, or a custom class from the project class path that implements `TestDataSource`. Required. |
| `poolSize` | `int` | `1` | Number of pooled connections (default 1; values of 1 or less keep 1). |
| `newResourceCheckoutTimeMs` | `long` | `1000` | Intended connection checkout wait, in ms (default 1000). Not passed to the data source in 5.0.0, so changing it has no effect. |
| `args` | `String[]` | *(unset)* | Connection arguments, in the order the class expects (see `GatfTestDataSource`). Required and non-empty. |

## GatfTestDataProvider

One entry of `providerTestDataList`: a named source of variable rows. Rows come either from a data source query (`dataSourceName` + `queryStr`) or from a `providerClass`; set exactly one of the two. XML root element: `<gatf-testdata-provider>`. Source: [`GatfTestDataProvider.java`](https://github.com/sumeetchhetri/gatf/blob/master/alldep-jar/src/main/java/com/gatf/executor/dataprovider/GatfTestDataProvider.java).

| Field | Type | Default | Description |
|---|---|---|---|
| `dataSourceName` | `String` | *(unset)* | Data source to query for rows (instead of `providerClass`). SQL sources need `queryStr`; MongoDB sources need `queryStr` and `sourceProperties`. |
| `providerName` | `String` | *(unset)* | Unique name of the provider, used by test cases, `authDataProvider` and seleasy `#provider` loops. Required. |
| `providerClass` | `String` | *(unset)* | Provider implementation instead of a data source: `com.gatf.executor.dataprovider.FileTestDataProvider`, `StateFulFileTestDataProvider`, `InlineValueTestDataProvider`, `RandomValueTestDataProvider` (same package), or a custom class implementing `TestDataProvider`. |
| `sourceProperties` | `String` | *(unset)* | MongoDB providers: comma-separated document property names to read, paired by position with `providerProperties`. Required for MongoDB. |
| `providerProperties` | `String` | *(unset)* | Comma-separated variable names each row provides (the column names). Required for every provider. |
| `queryStr` | `String` | *(unset)* | Query run against the data source: SQL for SQL sources, a JSON filter for MongoDB. For `live` providers it is templated against the calling test case first. |
| `enabled` | `Boolean` | *(unset)* | Set it to `true`. In 5.0.0 an unset value means disabled (the log says `Provider <name> is Disabled...`), although the loader intends `true`; a disabled provider is registered but returns no rows. |
| `args` | `String[]` | *(unset)* | Provider arguments. File providers: file path and type (`csv`, `xls`, `xlsx`, `xml` or `json`). Inline: one comma-separated row per arg (optional first arg `quoted=true`). Random: comma-separated value types and a row count. MongoDB: the collection name. |
| `live` | `Boolean` | *(unset)* | When `true` the rows are fetched again on every use (with `queryStr` templated against the test case) instead of once at start-up. |

## GatfTestDataSourceHook

One entry of `dataSourceHooks`: a named list of queries run against a data source at start-up, at shutdown, or when a test case names it as its pre/post execution hook. XML root element: `<gatf-testdata-source-hook>`. Source: [`GatfTestDataSourceHook.java`](https://github.com/sumeetchhetri/gatf/blob/master/alldep-jar/src/main/java/com/gatf/executor/dataprovider/GatfTestDataSourceHook.java).

| Field | Type | Default | Description |
|---|---|---|---|
| `hookName` | `String` | *(unset)* | Unique name of the hook, referenced by `preExecutionDataSourceHookName` / `postExecutionDataSourceHookName` on test cases. Required. |
| `hookClass` | `String` | *(unset)* | Custom hook class to run the queries instead of a data source; set either this or `dataSourceName`, not both. |
| `dataSourceName` | `String` | *(unset)* | Data source the queries run against; set either this or `hookClass`. |
| `queryStrs` | `String[]` | *(unset)* | The queries to run, in order. Required. At start-up and shutdown a failing query is logged; run from a test case, a failing query fails the case. |

## SeleniumDriverConfig

One entry of `seleniumDriverConfigs`: the settings `open <name>` uses to create a browser (driver binary, arguments, capabilities, preferences, remote URL). XML root element: `<seleniumDriverConfig>`. Source: [`SeleniumDriverConfig.java`](https://github.com/sumeetchhetri/gatf/blob/master/alldep-jar/src/main/java/com/gatf/selenium/SeleniumDriverConfig.java).

| Field | Type | Default | Description |
|---|---|---|---|
| `name` | `String` | *(unset)* | Browser key this entry configures, as written after `open` (e.g. `chrome`, `firefox`, `edge`, `appium-android`). |
| `version` | `String` | *(unset)* | Appium entries only: the device platform version (sent as `appium:platformVersion`). |
| `platform` | `String` | *(unset)* | Not read by the executor in 5.0.0. |
| `driverName` | `String` | *(unset)* | JVM system property that points the driver at its binary (e.g. `webdriver.chrome.driver`); it is set to `path` when that file exists. |
| `path` | `String` | *(unset)* | Path to the driver binary (e.g. chromedriver), applied through `driverName` when the file exists. `D_CHROME_DRIVER` / `D_FF_DRIVER` override it for Chrome and Firefox in the web console. |
| `arguments` | `String` | *(unset)* | Browser command-line arguments, separated by spaces. GATF adds its own managed flags (e.g. `--ignore-certificate-errors`, `--remote-allow-origins=*` for Chrome) without duplicating them. For Chrome keys 5.0.0 hands the whole string (managed flags included) to the browser as one argument, so only the first switch takes effect: give a single switch such as `--headless=new`. |
| `url` | `String` | *(unset)* | Remote endpoint for `remote-*` and Appium entries; unset means `http://127.0.0.1:4723/wd/hub` for `remote-*`. For Appium an environment or system-property URL wins over it. |
| `capabilities` | `Map<String, String>` | empty | Extra capabilities (name to value) set on the browser options. The keys `logconsole`, `logdebug` and `lognw` (`1`, `on` or `true`) are not sent: they turn on GATF's console, debug and network logging. |
| `properties` | `Map<String, String>` | empty | Browser preferences: Chrome `prefs` (experimental option) or Firefox profile preferences. |

## AiConfig

The opt-in `<ai>` block of the executor config. Absent (the default) means AI is not configured and nothing anywhere behaves differently. There is deliberately no key field: the key is read at call time from the environment variable `apiKeyEnv` (default per provider: `ANTHROPIC_API_KEY`, `OPENAI_API_KEY`) or from the file `apiKeyFile`, so it can never be serialized with the config, a report or a distributed run's payload. Cost fields are in whatever currency the prices are given in (per million tokens). XML root element: `<ai>`. Source: [`AiConfig.java`](https://github.com/sumeetchhetri/gatf/blob/master/alldep-jar/src/main/java/com/gatf/ai/AiConfig.java).

| Field | Type | Default | Description |
|---|---|---|---|
| `provider` | `String` | *(unset)* | `anthropic` \| `openai` \| `local` (an OpenAI-compatible endpoint) \| a plugin provider's name. |
| `model` | `String` | *(unset)* | Model id sent to the provider. Required: without it AI stays unconfigured. |
| `endpoint` | `String` | *(unset)* | Overrides the provider's default endpoint; required for `local`. |
| `apiKeyEnv` | `String` | *(unset)* | Name of the environment variable holding the key. |
| `apiKeyFile` | `String` | *(unset)* | Path of a file holding the key (first line), as an alternative to the environment. |
| `timeoutMs` | `Integer` | *(unset)* | Timeout per AI call, in ms (default 30000, clamped to 1000..600000). |
| `retries` | `Integer` | *(unset)* | Retries per call on timeouts, I/O errors, HTTP 429 and 5xx, with exponential backoff (default 2, clamped to 0..5). Other 4xx responses are not retried. |
| `maxCallsPerRun` | `Integer` | *(unset)* | Most calls one AI session (one healer or planner run) may make (default 10, clamped to 1..1000). |
| `maxTokensPerRun` | `Integer` | *(unset)* | Token budget (input plus output) for one AI session (default 50000, clamped to 1..10000000). Without usage data from the provider, tokens are estimated at about 4 characters each. |
| `maxOutputTokens` | `Integer` | *(unset)* | Most output tokens requested per call (default 1024, clamped to 16..32000), and never more than the session's remaining token budget. |
| `maxCostPerRun` | `Double` | *(unset)* | Cost budget for one AI session, in the currency of `inputCostPerMTok` / `outputCostPerMTok`. Unset = no cost limit. |
| `inputCostPerMTok` | `Double` | *(unset)* | Price per million input tokens, used to track cost against `maxCostPerRun`. |
| `outputCostPerMTok` | `Double` | *(unset)* | Price per million output tokens, used to track cost against `maxCostPerRun`. |

## HttpServerSimulatorConfig

XML root element: `<htttpServerSimulator>`. Source: [`HttpServerSimulatorConfig.java`](https://github.com/sumeetchhetri/gatf/blob/master/alldep-jar/src/main/java/com/gatf/executor/core/HttpServerSimulatorConfig.java).

| Field | Type | Default | Description |
|---|---|---|---|
| `enabled` | `boolean` | `false` | Start the HTTP simulator (default `false`). |
| `port` | `int` | `0` | Port to listen on; must be 80 or above when enabled. |
| `body` | `String` | *(unset)* | Response body returned for every request. Required when enabled. |
| `headers` | `Map<String, String>` | empty | Response headers (name to value) returned with every response. |
