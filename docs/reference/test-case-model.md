# Test case model

> Generated by `tools/gen-docs` from the GATF sources. Do not edit this page by hand: change the source or `tools/gen-docs/descriptions/case-model.properties`, then run `java tools/gen-docs/GenDocs.java generate`.

A test file under `testCaseDir` holds API test cases: XML (`<TestCases>` with `<TestCase>` children), a JSON array of objects, or CSV rows. Each case is one HTTP (or SOAP) call with its assertions. In XML a field is a child element of the same name (lists are wrapper elements, maps are child elements named after the key); in JSON it is a key. The [test case concept page](../guide/concepts/test-cases.md) shows the common patterns; this page lists every field.

Types on this page: [`TestCase`](#testcase) · [`PerformanceConfig`](#performanceconfig)

## TestCase

One API test case: a request, the assertions on its response, and the variables it captures for later cases. Cases are loaded from XML, JSON, CSV, XLS or XLSX files under the configured test-case directory. XML root element: `<TestCase>`. Source: [`TestCase.java`](https://github.com/sumeetchhetri/gatf/blob/master/alldep-jar/src/main/java/com/gatf/executor/core/TestCase.java).

| Field | Type | Default | Description |
|---|---|---|---|
| `baseUrl` | `String` | *(unset)* | Scheme and host (plus any path prefix) the `url` is appended to. When blank, the configured `baseUrl` of the run is used; if set it must be a valid URL. Not needed for `soapBase` cases. |
| `url` | `String` | *(unset)* | Path (and optional query string) appended to `baseUrl`. Required unless `soapBase` is `true`; `${var}` placeholders are resolved from global, workflow and scenario variables before the call. |
| `name` | `String` | *(unset)* | Name of the case, required. It is the key used by `relatedTestName`, by pre/post hooks registered for this case, and in reports. |
| `method` | `String` | *(unset)* | HTTP method: `GET`, `POST`, `PUT`, `DELETE` or `PATCH` (case-insensitive). Required unless `soapBase` is `true`. |
| `description` | `String` | *(unset)* | Free text shown in logs and reports; null is stored as an empty string. |
| `content` | `String` | *(unset)* | Request body, sent as written after `${var}` resolution. When non-blank it takes precedence over `multipartContent` and `contentFile`, and it is not sent for `GET`. A `Content-Type` header is required when `content` or `contentFile` is set on a non-SOAP case. |
| `contentFile` | `String` | *(unset)* | Path of a file whose contents are sent as the request body, read relative to the test-cases base path. Used only when `content` and `multipartContent` are not applicable; for SOAP cases the file is sent Base64-encoded as a parameter value. |
| `headers` | `Map<String, String>` | empty | Request headers as name/value pairs. Names matching a known HTTP header are normalised to its canonical spelling, values accept `${var}`, and a stored cookie for the host is merged into `Cookie`. |
| `exQueryPart` | `String` | *(unset)* | Extra query string (without the leading `?`) appended to `url` with `?` or `&` as appropriate. `${var}` placeholders are resolved. |
| `expectedResCode` | `int` | `0` | Expected HTTP status code. `0` (or a negative value) disables the check; otherwise a different status fails the case, and with `abortOnInvalidStatusCode` it fails immediately. |
| `expectedResContentType` | `String` | *(unset)* | Expected response `Content-Type`, matched as a prefix of the actual header. It also sets the `Accept` request header and selects the JSON, XML or text response validator; when blank, the type returned by the server is used. |
| `expectedResContent` | `String` | *(unset)* | Expected response body text. Serialized and shown in generated API docs, but not compared with the response by the executor in 5.0.0. |
| `skipTest` | `boolean` | `false` | When `true` the case is not executed and is reported as skipped. |
| `detailedLog` | `boolean` | `false` | When `true` and debug is enabled in the run configuration, the case and its report are written to the log; the cURL line is also logged for this case. |
| `secure` | `boolean` | `false` | When `true`, the session token captured from the configured auth URL is attached to the request (query parameter, header or cookie, as set by the auth-extract settings). Has no effect on the auth case itself. |
| `expectedNodes` | `List<String>` | empty | Response assertions, one per entry. A plain JSON path or XPath must resolve to a non-null value; an entry may also compare a node, `#responseHeader[..]`, `#responseCookie[..]` or `#providerValidation[..]` with a value using an operator. Entries accept `${var}`. |
| `soapBase` | `boolean` | `false` | `true` marks a SOAP case: the request is built from the WSDL operation selected by `wsdlKey` and `operationName`, and the SOAP response validator is used. `method` and `url` are not required. |
| `wsdlKey` | `String` | *(unset)* | Key of the WSDL (from the run's `wsdlLocFile` configuration) to use. Required when `soapBase` is `true`. |
| `operationName` | `String` | *(unset)* | Name of the WSDL operation to call. Required when `soapBase` is `true`. |
| `soapParameterValues` | `Map<String, String>` | empty | Values (name to value) filled into the generated SOAP request when no `content` is given. Multipart file/text parts of a SOAP case are also added here. |
| `workflowContextParameterMap` | `Map<String, String>` | empty | Variables to capture from the response for use in later cases as `${name}`. Each key is the variable name (letters, digits, underscore; starting with a letter or underscore) and each value a response node or one of `#responseHeader[..]`, `#responseCookie[..]`, `#responseMappedValue[..]`, `#responseMappedCount[..]`. |
| `sequence` | `int` | `0` | Ordering key: cases are sorted by ascending `sequence` after the auth case, which always runs first. A value of zero or less is replaced by the case's position in the sorted list. |
| `multipartContent` | `List<String>` | empty | Multipart/form-data parts, each written as `name:type:value` or `name:type:value:mime`. `type` is `text` or `file`; for `text` the mime type is required, for `file` the value is a path under the test-cases base path. Ignored when `content` is sent. |
| `outFileName` | `String` | *(unset)* | Not read by the executor in 5.0.0; the value is stored and serialized only. |
| `repeatScenarios` | `List<Map<String, String>>` | empty | Inline list of variable maps; the case runs once per map, with that map's entries available as `${var}` and to `logicalValidations`. Cannot be combined with `repeatScenarioProviderName`. |
| `repeatScenarioProviderName` | `String` | *(unset)* | Name of a test-data provider (or of a list captured earlier with `#responseMappedValue[..]`) whose rows drive the scenario runs; the case runs once per row. Cannot be combined with `repeatScenarios`. |
| `numberOfExecutions` | `Integer` | `1` | Performance mode: with a value greater than 1 and no `perfConfig`, the case runs once, then this many further concurrent copies are run and timings are reported. The executor resets it to 1 for cases without `repeatScenarioProviderName`. Default `1`. |
| `repeatScenariosConcurrentExecution` | `boolean` | `false` | When `true`, all scenario runs are sent without waiting for each response; when `false` (default) each run completes, and its `logicalValidations` are checked, before the next starts. |
| `stopOnFirstFailureForPerfTest` | `boolean` | `false` | In performance mode (`numberOfExecutions`), skip the concurrent runs when the first, single run fails. |
| `preWaitMs` | `Long` | *(unset)* | Milliseconds to sleep after the request is built and before it is sent. Null, zero or negative means no wait; skipped when `disablePreHooks` is `true`. |
| `postWaitMs` | `Long` | *(unset)* | Milliseconds to sleep after the response has been validated. Null, zero or negative means no wait; skipped when `disablePostHooks` is `true`. |
| `reportResponseContent` | `Boolean` | `true` | When `false`, the response body is dropped from the generated report for this case. Default `true`. |
| `preExecutionDataSourceHookName` | `String` | *(unset)* | Name of a configured data-source hook (for example SQL set-up) run before the request is built. A failure is logged and does not fail the case; skipped when `disablePreHooks` is `true`. |
| `postExecutionDataSourceHookName` | `String` | *(unset)* | Name of a configured data-source hook (for example SQL clean-up) run after the case has executed. A failure is logged and does not fail the case; skipped when `disablePostHooks` is `true`. |
| `abortOnInvalidStatusCode` | `boolean` | `false` | When `true` and the status differs from `expectedResCode`, the case fails immediately and the rest of response handling (body capture, node validation) is skipped. |
| `abortOnInvalidContentType` | `boolean` | `false` | When `true` and the response `Content-Type` does not start with `expectedResContentType`, the case fails immediately and the rest of response handling is skipped. |
| `relatedTestName` | `String` | *(unset)* | Name of another case (or cases) to run after this one succeeds. Related cases inherit this case's `baseUrl` and, for scenario runs, its scenario variables. |
| `executeOnCondition` | `String` | *(unset)* | Velocity boolean expression evaluated before the case runs; when it is false the case is skipped and the condition is recorded as the reason. |
| `logicalValidations` | `List<String>` | *(unset)* | Velocity boolean expressions (for example `$token != ""`) evaluated with the global, captured workflow and scenario variables in scope, not the raw response; on a plain case they run before this case's own captures. For scenario runs (`repeatScenarios`, `repeatScenarioProviderName`) they are evaluated per scenario. In 5.0.0 a false expression did not fail a plain case (no scenarios) in our checks, so do not rely on it there; use `expectedNodes` instead. |
| `disablePreHooks` | `boolean` | `false` | When `true`, the pre-execution Java hooks, `preExecutionDataSourceHookName` and `preWaitMs` are skipped for this case. Default `false`. |
| `disablePostHooks` | `boolean` | `false` | When `true`, the post-execution Java hooks, `postExecutionDataSourceHookName` and `postWaitMs` are skipped for this case. Default `false`. |
| `perfConfig` | [`PerformanceConfig`](#performanceconfig) | *(unset)* | Load-test settings (`PerformanceConfig`). When `perfConfig.type` names an engine, the case is handed to that load tool instead of the normal request/validation path, and `numberOfExecutions` and scenario repeats are not used. |
| `contract` | `String` | *(unset)* | `<spec file>#<operation pointer>`; the response is validated against that OpenAPI operation. |
| `contractHash` | `String` | *(unset)* | Fingerprint of the operation when the case was generated (drift on re-import). |

Also accepted when reading a file (setter names that differ from the field):

| Name | Same as |
|---|---|
| `serverApiAuth` | `isServerApiAuth` |
| `serverApiTarget` | `isServerApiTarget` |
| `externalApi` | `isExternalApi` |

Also serialized, but not meant to be set in a config file:

| Field | Why |
|---|---|
| `simulationNumber` | run/user index assigned by GATF (reset to 0 at start; set per simulated user when concurrent user simulation is on); it names the run in reports and selects the login data row. |

## PerformanceConfig

Load-test settings for one case, mapped onto the command line of the chosen engine. Unset or `0` numeric fields fall back to the defaults given per field. XML root element: `<wrkConfig>`. Source: [`PerformanceConfig.java`](https://github.com/sumeetchhetri/gatf/blob/master/alldep-jar/src/main/java/com/gatf/executor/core/PerformanceConfig.java).

| Field | Type | Default | Description |
|---|---|---|---|
| `type` | `String` | *(unset)* | Load engine: `wperfk` (recommended; wrk/wrk2-compatible, any OS, Lua scripts), `vegeta`, `autocannon`, `wrk`, `wrk2`, or the name of an engine provided by a jar in `plugins/`. Blank, absent or `none` runs the case as a normal functional test; an unknown name fails the case. The wrk family falls back to vegeta when its binary is unavailable. |
| `connections` | `int` | `0` | Concurrent connections. `wrk`, `wrk2`, `wperfk`: `-c`, null, zero or negative = 10; `vegeta` and `autocannon`: passed only when positive. With `vegeta` and `extras` `closed=1` and no `rate`, it is the number of concurrent workers (default 10). |
| `durationSeconds` | `int` | `0` | Test duration in seconds; zero or negative means 10 for every engine. |
| `threads` | `int` | `0` | Worker threads. `wrk` family: `-t`, zero or negative = 10 and never more than `connections`; `vegeta`: `-workers` and `autocannon`: `-w`, passed only when positive. |
| `rate` | `int` | `0` | Target requests per second. `wrk2`: `-R`, zero or negative = 1000; `wperfk`: `-R` only when positive, otherwise closed-loop maximum throughput; `vegeta` and `autocannon`: constant rate when positive; `wrk`: not used. |
| `filePath` | `String` | *(unset)* | Resource path (resolved like other test resources). `wrk` family: a Lua script passed with `-s`; if unset or missing, a script is generated from the case's method, headers and body. `vegeta` and `autocannon`: request body file for non-GET requests (ignored by vegeta when it runs as a wrk fallback). |
| `timeout` | `int` | `0` | Request timeout in seconds, passed to the engine only when positive (`--timeout`, `-timeout` or `-t`). |
| `latency` | `boolean` | `false` | When `true`, adds `--latency` (latency distribution) to `wrk`, `wrk2` and `wperfk`; not read by `vegeta` or `autocannon`. |
| `extras` | `String` | *(unset)* | Read by the `vegeta` engine only: `closed=1` runs a closed loop of `connections` workers when no `rate` is set, and `plot=1` also produces an HTML plot. The flags are looked up as substrings of the string (`closed=1` must be delimited by space, comma, semicolon or `&`). |
