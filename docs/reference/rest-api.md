# Server REST API

> Generated by `tools/gen-docs` from the GATF sources. Do not edit this page by hand: change the source or `tools/gen-docs/descriptions/rest.properties`, then run `java tools/gen-docs/GenDocs.java generate`.

`gatf ui [port] [dir]` starts an HTTP server (default `127.0.0.1:9080`) that serves the web console at `/app/` and the endpoints below, which the console itself uses. Requests and responses are JSON unless noted. When `auth.props` in the folder the server was started from (its working directory) defines users, every endpoint except `/login` needs the session from `/login`; otherwise the server runs in anonymous mode (the startup log says `Running in anonymous mode`). The routes, query parameters and actions below are read from the handler sources; the descriptions say which HTTP methods each one accepts and what it does. These endpoints serve the console: they have no versioning promise beyond `/api` (`"api": "v1"`).

| Path | Kind | Description |
|---|---|---|
| [`/`](#-root) | HTTP | Root of the web console server. |
| [`/api`](#api) | HTTP | Read-only JSON API used by the React console; every call is a `GET` (any other method answers `405`) and the sub-resource is the path segment after `/api/`. |
| [`/app`](#app) | HTTP | Static React console (Vite build extracted from the packaged `gatf-viewer` resources into an `app` folder under the server root). |
| [`/configure`](#configure) | HTTP | Reads and saves the executor and generator configuration, chosen by the `configType` query parameter (`executor` or `generator`). |
| [`/crawl`](#crawl) | HTTP | Browser-driven (SPA-aware) crawl that generates a seleasy `.sel` suite plus a coverage plan from a seed URL. |
| [`/execute`](#execute) | HTTP | Starts, polls and stops a test run in the background, selected by the `pluginType` query parameter (`executor-api` runs the API suite; any other `executor-` value runs the selenium scripts, and a non-`executor-` value uses the generator config). |
| [`/gatfjdb`](#gatfjdb) | WebSocket | WebSocket (not HTTP) push channel for the online seleasy debugger. |
| [`/import`](#import) | HTTP | Converts an external test source into GATF tests. |

| [`/projectZip`](#projectzip) | HTTP | Builds two project archives, a binary-style and a Maven-style package of the test directory, output directory and top-level files, and writes them as `gatf-test-bin.zip` and `gatf-test-mvn.zip` under the `gatf-config-tool` folder of the server root. |

## / (root)

Root of the web console server. Any request answers `302` with `Location: /app/`, so a browser opening the server lands on the React console.

- Handler: inline in `GatfConfigToolUtil`

## /api

Read-only JSON API used by the React console; every call is a `GET` (any other method answers `405`) and the sub-resource is the path segment after `/api/`. `/api` and `/api/health` return the health object, an unknown segment answers `404`, and most sub-resources accept `config=<relative config file>` to pick the config they read.

- Handler: `GatfApiHandler`
- Query parameters: `after`, `config`, `crawl`, `file`, `full`, `limit`, `path`, `report`

Sub-resources (`/api/<name>`):

| Value | Description |
|---|---|
| `health` | `GET /api/health` (same as `GET /api`) returns `{"ok": true, "service": "gatf", "api": "v1"}`; a liveness check for the console. |
| `plugins` | `GET /api/plugins` lists every plugin a seleasy script can call (built-ins, `plugins.txt` entries and SDK plugin jars) with name, kind, summary, usage, args, examples and source, for script completion. |
| `history` | `GET /api/history?limit=N` returns the newest `N` archived run results (default 10), newest first, as `dir` plus `runs` with id, time, summary and compact per-test status and duration. A non-numeric `limit` answers `400`. |
| `live` | `GET /api/live?file=<script>&after=<seq>` returns the newest screencast frame of a running script as `image/jpeg` with `X-Frame-Seq`, `X-Frame-Ts` and `X-Frame-Ended` headers, or `204` when there is nothing newer. Frames exist only when the config has `traceVideo` on; `file` is required and `after` must be numeric. |
| `reports` | `GET /api/reports` returns the output directory (`dir`) and one row per run folder found under it (up to 4 levels deep) with name, url, size, modified, `type` (`API`, `Selenium`, `Load` or `Merged`), `label`, optional `dataUrl` and the folder's trace zips, newest first. |
| `configs` | `GET /api/configs` lists the selectable config files: `gatf-config*.json` and `gatf-config*.xml` in the server root (source `root`) and every `.json` or `.xml` under `configs/` (source `configs`), sorted by name. |
| `config` | `GET /api/config` returns the effective executor config as `config`, together with the resolved test directory (`testDir`) and output directory (`outDir`). The `config` query parameter selects a config file. |
| `testfiles` | `GET /api/testfiles` lists the `.sel` and `.xml` files directly in the test directory (not sub-folders) as `dir` plus `files` with name, path, size, modified and `kind` (`sel` or `xml`). |
| `testfile` | `GET /api/testfile?path=<relative>` returns one test file as `path`, `kind`, `size`, `truncated` and `content`; content is cut at 512 KB. A missing `path` or one that escapes the test directory answers `400`, an absent file `404`. |
| `coverage` | `GET /api/coverage?report=<reports row name>` returns the coverage index of that row's run folder (built from its trace zips and merged with a crawl map from the test directory), as a summary unless `full=1`, plus `crawls`, the available crawl map names. `crawl=<name>-coverage.json` picks a map (default newest); a bad `report` or `crawl` answers `400`. It may write a `coverage-index.json` cache in the run folder. |

## /app

Static React console (Vite build extracted from the packaged `gatf-viewer` resources into an `app` folder under the server root). Served with no-cache headers, `GET` only, and not token-gated even when `auth.props` is present; the console's own calls to the other routes carry the token.

- Handler: `CacheLessStaticHttpHandler`

## /configure

Reads and saves the executor and generator configuration, chosen by the `configType` query parameter (`executor` or `generator`). `GET` returns the config as JSON, creating a default config file first if none exists; `POST` takes the config JSON as the body, writes it back to its file, and returns it. Failures answer `400` (POST) or an error body (GET).

- Handler: `GatfConfigurationHandler`
- Query parameters: `config`, `configType`

Values of `configType`:

| Value | Description |
|---|---|
| `executor` | With `configType=executor`: `GET` returns the executor config (`gatf-config.json`, else `.xml`, or the file named by `config`), creating a default one if missing. `POST` with a `GatfExecutorConfig` JSON body saves it to that file, then initialises a context from it as a check and returns the config JSON; an invalid config answers `400` after the save. |
| `generator` | With `configType=generator`: `GET` returns the test-generator config from `gatf-generator.xml` (created if missing). `POST` with a generator config JSON body writes it back to `gatf-generator.xml` (defaulting `resourcepath` to `generated` under the server root) and returns it. |

## /crawl

Browser-driven (SPA-aware) crawl that generates a seleasy `.sel` suite plus a coverage plan from a seed URL. Selected by `action` (`start`, `status`, `stop`, `result`, `save`); `start` and `save` require `POST` (or `PUT`) and answer `405` otherwise, while `status`, `stop` and `result` also work with `GET`; every action except `start` needs `sessionId`, and an unknown session answers `404`. At most 2 crawls run at once, and finished sessions are dropped after 1 hour.

- Handler: `GatfCrawlHandler`
- Query parameters: `action`, `config`, `fileName`, `sessionId`

Values of `action`:

| Value | Description |
|---|---|
| `start` | `POST /crawl?action=start` with a JSON body (`seed` must be an `http(s)` URL; optional `maxPages` 1-500 default 25, `maxDepth` 0-10 default 3, `submitForms`, `headless` default true, `browser`, `exclude` regex, `suiteName`, and login fields `loginUrl`, `username`, `password`, `userSel`, `passSel`, `submitSel`) starts a crawl and returns `{sessionId}`. A bad body answers `400`; with 2 crawls already running it answers `503`. |
| `status` | `GET /crawl?action=status&sessionId=<id>` returns the live state of the crawl (running, done, pages visited and queued, current page, discovered pages and log). Unknown session answers `404`. |
| `stop` | `POST /crawl?action=stop&sessionId=<id>` asks the crawl to stop and returns its status. |
| `result` | `GET /crawl?action=result&sessionId=<id>` returns the generated suite as `content` and the per-page `coverage` plan; answers `409` while the crawl is running or if it produced no result. |
| `save` | `POST /crawl?action=save&sessionId=<id>&fileName=<name>` writes the generated suite as `<name>.sel` and `<name>-coverage.json` into the test directory (name sanitised; defaults to the suite name) and returns `savedPath`, `coveragePath` and the parse `validation` text. Answers `409` if there is nothing to save yet. |

## /execute

Starts, polls and stops a test run in the background, selected by the `pluginType` query parameter (`executor-api` runs the API suite; any other `executor-` value runs the selenium scripts, and a non-`executor-` value uses the generator config). `PUT` starts a run with a JSON array of test file names as the body (optional `grep`, `grepInvert`, `tag` filters, `config`), `GET` polls progress or collects the result, and `DELETE` interrupts the run. Only one run is tracked at a time.

- Handler: `GatfPluginExecutionHandler`
- Query parameters: `config`, `grep`, `grepInvert`, `pluginType`, `tag`

Values of `pluginType`:

| Value | Description |
|---|---|
| `executor-api` | `pluginType=executor-api` runs the API test suite (`doExecute` with the posted file list). `PUT` starts it (body: JSON array of file names; optional `grep`, `grepInvert`, `tag`) and returns `Execution Started` with `loadTestingEnabled`; `GET` polls (progress as an error-style JSON while running, then `Execution completed, check Reports Section` with report `paths`); `DELETE` interrupts it. |

## /gatfjdb

WebSocket (not HTTP) push channel for the online seleasy debugger. The client opens `ws://<host>/gatfjdb` and sends the debug `sessionId` as its first text message; the server then pushes JSON frames with keys `s`, `r`, `p`, `n`, `v`, `t` (ok, running, previous line, next line, state, current file) whenever the debugger changes. It is push-only: debugger commands go over `PUT /reports?action=debug`, and the handler does not check the auth token.

- Handler: `GatfDebugWebSocket`

## /import

Converts an external test source into GATF tests. `POST` or `PUT` with the raw source as the body and `type` (`playwright`, `jmeter`, `curl`, `postman`, `har`, `openapi`, plus the flow-to-load type) previews the conversion and returns `content`, `kind`, `unsupported` constructs and `stats`; with `save=true` it also writes the file into the test-case directory (`fileName` optional). Bad or empty input answers `400`, other methods `405`.

- Handler: `GatfImportHandler`
- Query parameters: `bundle`, `config`, `duration`, `engine`, `fileName`, `filter`, `negative`, `overwrite`, `rate`, `save`, `type`, `users`

## /login

Exchanges credentials for a session token when the server was started with an `auth.props` file. `POST` form fields `username` and `password`; a match returns `{"token": ...}` with `200`, anything else `401`. Pass the token as the `token` query parameter on every other call; it is refreshed on each use and expires after `session.timeout` ms from `auth.props` (default 30 minutes). Without `auth.props` the server runs anonymously, no token is needed, and this route returns an empty `200`.

- Handler: inline in `GatfConfigToolUtil`

## /misc

`GET` returns the option lists the console's forms need as a JSON map: `datasources`, `providers`, `hooks` (names from the config's test-data section), `datasourcecls`, `providercls` (built-in class names) and `dirs` (sub-directories of the test-case directory). With `action=testdocs` it instead downloads the generated test documentation (`format=xlsx` default, or `csv` as a zip).

- Handler: `GatfMiscHandler`
- Query parameters: `action`, `config`, `format`

## /profile

`GET` returns statistics profiled from the configured test-data data sources, as a JSON map of data source name to rows of strings. `dsnames` selects data sources by name (a blank value or `all` profiles every one) and `config` picks the config file; any failure answers a generic error.

- Handler: `GatfProfileHandler`
- Query parameters: `config`, `dsnames`

## /projectZip

Builds two project archives, a binary-style and a Maven-style package of the test directory, output directory and top-level files, and writes them as `gatf-test-bin.zip` and `gatf-test-mvn.zip` under the `gatf-config-tool` folder of the server root. Any method triggers it; the response lists the packages built (`binary`, `maven`) with `200`, or the error messages with `500`. It does not stream the zip.

- Handler: `GatfProjectZipHandler`

## /record

Record mode: infers a seleasy test from live user actions in a visible local browser, and also hosts the pick-locator and step-healing helpers. Selected by `action`; `start`, `rank`, `pick`, `stop`, `save`, `heal` and `healApply` require `POST` (or `PUT`), and session-bound actions need `sessionId` (unknown session answers `404`).

- Handler: `GatfRecordHandler`
- Query parameters: `action`, `browser`, `config`, `fileName`, `on`, `sessionId`, `url`

Values of `action`:

| Value | Description |
|---|---|
| `start` | `POST /record?action=start&url=<startUrl>` (optional `browser`) launches a visible local browser with a recorder and returns `{sessionId, running: true}`; a launch failure answers `500`. |
| `rank` | `POST /record?action=rank` with a JSON body of candidate locators and a selector ranks them, with no session needed; returns the ranking (`400` for a bad body, `413` for an over-cap one). |
| `tid` | `GET /record?action=tid` returns `{testIdAttribute}`, the config's test-id attribute, defaulting to `data-testid`. |
| `list` | `GET /record?action=list` returns `{sessions}`, the recordings still running, each with `sessionId` and `browser`. |
| `heal` | `POST /record?action=heal` with a JSON body (`trace`, `file`, `step`, all optional) analyses a failed step from its trace and returns the healer's proposals plus `file`, `line`, `trace` and a `healId`. It writes nothing. |
| `healApply` | `POST /record?action=healApply` with body `healId` and `rank` applies one of the proposals from a prior `heal` to the script after validating it; returns `status` `applied` (200), `conflict` (409) or `invalid` (422). |
| `steps` | `GET /record?action=steps&sessionId=<id>` returns the steps recorded so far as `running`, `lines`, `count` and `error` if the recording failed; the console polls it. |
| `pick` | `POST /record?action=pick&sessionId=<id>&on=true\|false` arms or disarms the in-page element picker and returns `{armed}`; `409` if the session is not running. |
| `picked` | `GET /record?action=picked&sessionId=<id>` returns `running`, `armed` and the last picked element (`pick`). |
| `stop` | `POST /record?action=stop&sessionId=<id>` ends the recording and returns the generated seleasy script as `content`, with `lines` and `count`. |
| `save` | `POST /record?action=save&sessionId=<id>&fileName=<name>` stops the recording and writes it as `<name>.sel` (default `recorded`; name sanitised) in the test directory, drops the session, and returns `saved`, `savedPath` and the parse `validation` text. |

## /reports

Serves report files from the configured output directory on `GET` (a static file handler, no cache), plus the report path index and the debug SSE stream. `PUT` with an `action` runs single tests, the debugger and run controls; most PUT actions take `testcaseFileName`, `testCaseName` and `sessionId`, and an unrecognised action fails with `Invalid action specified..`.

- Handler: `GatfReportsHandler`
- Query parameters: `action`, `config`, `isExternalLogsApi`, `isServerLogsApi`, `line`, `sessionId`, `testCaseName`, `testcaseFileName`, `type`

Values of `action`:

| Value | Description |
|---|---|
| `paths` | `GET /reports?action=paths&type=<api\|sel>` returns `{paths}`, the run sessions and report folders of that type known to this server process, newest first. |
| `debugStream` | `GET /reports?action=debugStream&sessionId=<id>` opens a Server-Sent Events stream of debugger frames with keys `s`, `r`, `p`, `n`, `v`, `t`, pushed on every change until the script stops; the fallback to the `/gatfjdb` WebSocket. |
| `validateTest` | `PUT /reports?action=validateTest&testcaseFileName=<file>.sel` parse-validates a seleasy script against the config and returns the validation text as JSON; only applies to `.sel` files. |
| `replayTest` | `PUT /reports?action=replayTest&testcaseFileName=<file>&testCaseName=<name>` re-runs one API test case re-sending a captured request: the body is the `TestCaseReport` JSON whose actual URL, content and headers replace the definition. Returns the new report JSON. |
| `playTest` | `PUT /reports?action=playTest&testcaseFileName=<file>&testCaseName=<name>` runs one test as defined, with no captured-request override: an `.xml` test case returns its report JSON, a `.sel` file runs the whole script and returns a pointer to the reports. Also drives the server-logs and external API cases when `isServerLogsApi` or `isExternalLogsApi` is passed. |
| `debug` | `PUT /reports?action=debug&testcaseFileName=<file>.sel&sessionId=<id>&line=<code>` is the debugger command channel. `line` is `0` to start a session (returns source `c`, debuggable lines `l`), `-1` step into (needs `sline`), `-2` step out, `-3` step over, `-4` continue, `-5` suspend, `-6` terminate, `-7` status, `b<n>` or `r<n>` to set or remove a breakpoint at line `n`. |
| `createIssue` | `PUT /reports?action=createIssue&isExternalLogsApi=true&testcaseFileName=<file>&testCaseName=<name>` sends the issue-tracker API test case with the body's `url` and `requestContent` and returns its report JSON. Without `isExternalLogsApi` the action is rejected. |
| `getContent` | `PUT /reports?action=getContent&isExternalLogsApi=true&testcaseFileName=<file>&testCaseName=<name>` with a failed `TestCaseReport` as the body renders the issue API's URL and body templates against that report and returns them as `url` and `requestContent`; if the template has no body it executes the API case instead. |
| `pauseElSearch` | `PUT /reports?action=pauseElSearch` pauses the element search of the running selenium script and returns `file`, `line`, `is_paused` and `running`; `{"status": false, "running": false}` when nothing is running. |
| `unPauseElSearch` | `PUT /reports?action=unPauseElSearch` resumes a paused element search and returns `file`, `line`, `is_paused` and `running`; `{"status": false, "running": false}` when nothing is running. |
| `restartSubtest` | `PUT /reports?action=restartSubtest` restarts the subtest currently executing in the running script and returns `{"status": true}`, or `{"status": false}` when nothing is running. |
| `stop` | `PUT /reports?action=stop` stops the running script execution and returns `{"status": true}`, or `{"status": false}` when nothing is running. |
| `pausedLineNo` | `PUT /reports?action=pausedLineNo` returns the paused `file` and `line`, `is_paused` and `running`; `{"line": -1, "running": false}` when nothing is running. |

## /testcasefiles

Manages the test files in the test-case directory (`.xml`, `.sel`, `.props`). `POST` creates an empty file, `PUT` renames it or stores `extras`, `DELETE` removes it, and `GET` lists the files (or answers subtest and referenced-file lookups). File names are passed as the `testcaseFileName` query parameter; `config` picks the config file.

- Handler: `GatfTestCaseFilesHandler`
- Query parameters: `allsubtests`, `config`, `extras`, `possibleSubtestFuncCall`, `referencedFile`, `testcaseFileName`, `testcaseFileNameTo`

## /testcases

Reads and edits the content of one test file named by `testcaseFileName`. `GET` returns an `.xml` file as a JSON array of test cases (any other file as plain text); `POST` or `PUT` saves it (a `.bak` copy is made first and `.sel` content is parse-checked); `DELETE` removes one test case from an `.xml` file, named by the `testcasename` header. Without `testcaseFileName` it answers `500`.

- Handler: `GatfTestCaseHandler`
- Query parameters: `config`, `configType`, `tcName`, `testcaseFileName`

Values of `configType`:

| Value | Description |
|---|---|
| `loggingapi` | `configType=loggingapi` addresses the server-logs API definition file (`gatf-logging-api-int.xml`) under the server root instead of the test directory. `GET` returns its `authapi` and `targetapi` test cases, adding default ones to the file if missing; saves accept only those two names. |
| `issuetrackerapi` | `configType=issuetrackerapi` addresses the issue-tracker API definition file (`gatf-issuetracking-api-int.xml`) under the server root instead of the test directory. `GET` returns its `authapi` and `targetapi` test cases, adding default ones to the file if missing; saves accept only those two names. |
